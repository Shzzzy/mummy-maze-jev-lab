# DeepSeek + Jev 分职责决策设计

- 日期：2026-09-21
- 状态：已确认
- 目标版本：木乃伊迷宫实验版

## 1. 目标

将当前“Jev 直接选择方向”的 AI 模式改为三方分职责：

1. DeepSeek 只分析局面，输出结构化中性事实和面向 Jev 的聚焦说明。
2. 代码注入固定规则与固定评分维度，不根据方向临时改写。
3. Jev 对 up、down、left、right 四个动作分别评分并返回置信度。
4. 代码在合法动作中选择分数最高的动作并执行。

DeepSeek 不输出方向建议、动作排序、风险与动作的绑定关系，也不参与最终动作选择。

## 2. 非目标

- 不引入持久化记忆或跨会话学习。
- 不让 DeepSeek 代替规则引擎判断合法性。
- 不让 Jev 继续直接承担方向选择。
- 不改变游戏规则、关卡数据和胜负判定。
- 不为高风险动作增加本地 AI 兜底；代码只负责合法性过滤和分数选择。

## 3. 架构

```text
浏览器
  -> POST /api/decide
      -> DeepSeek 分析器
          - 输入：完整游戏快照
          - 输出：中性 facts JSON
      -> 决策上下文组装器
          - 注入固定 rules
          - 注入固定 scoringDimensions
          - 过滤不可通行方向
      -> Jev System One
          - 对每个合法方向独立发出一个 score 问题
          - 返回 score、confidence、probabilities、legend
      -> 代码选择器
          - 选最高 score
          - 同分时选更高 confidence
          - 仍同分时按 up、down、left、right 固定顺序
      -> 返回完整评分卡给浏览器
```

## 4. 职责边界

### 4.1 DeepSeek

允许输出：

- 玩家、怪物、出口、闸门状态等中性事实。
- 四方向相邻地块及其类型。
- 只允许固定白名单字段，不允许额外自由文本或摘要。

禁止输出：

- “应该向上”“左边更安全”等方向建议。
- 动作排名。
- 对某个动作的分数或置信度。
- 修改游戏规则。

### 4.2 代码

- 合法性过滤：墙、关闭闸门、越界方向不进入 Jev 评分。
- 固定规则：使用代码中的权威规则表。
- 固定评分维度：使用代码中的权威评分维度表。
- 最终选择：只负责排序、同分处理和错误处理。
- 输出校验：校验 DeepSeek facts 和 Jev score 的结构。

### 4.3 Jev

- 对每个合法动作独立评分。
- 不读取其他动作的评分结果。
- 返回 score、confidence、probabilities、legend、type。
- 不负责最终选择，也不负责执行。

## 5. 固定规则表

规则由代码维护，DeepSeek 不能改写：

- 玩家每次只能移动一格，移动后怪物才行动。
- 玩家进入出口立即通关。
- 玩家进入陷阱立即失败。
- 玩家进入怪物所在格或怪物进入玩家所在格立即失败。
- 白木乃伊优先水平追击，每回合最多移动两步。
- 红木乃伊优先垂直追击，每回合最多移动两步。
- 蝎子优先水平追击，每回合只移动一步。
- 怪物被墙、关闭闸门、边界或另一只怪物阻挡时停止。
- 任意单位进入钥匙格时切换全部闸门状态。
- 关闭的闸门阻挡所有单位，打开的闸门可通行。

## 6. 固定评分维度

评分维度由代码维护，Jev 使用统一的 0-5 有序档位：

- 0：执行后立即失败或几乎必然失败。
- 1：风险很高，只有在没有其他可行动作时才合理。
- 2：风险较高或明显浪费回合，但没有立即失败。
- 3：风险可控，但既没有明显进展也没有明显损失。
- 4：风险较低，并且对通关有明确帮助。
- 5：安全性、进展性和后续机动性综合最佳。

评分为每个动作的独立总分，不要求 Jev 返回解释文本。

## 7. Jev 请求

每个合法动作对应一个独立 question，键名固定为 `up_score`、`down_score`、`left_score`、`right_score`。

示例：

```json
{
  "model": "jev-latest",
  "state": {
    "facts": {},
    "rules": [],
    "scoringDimensions": []
  },
  "questions": {
    "up_score": {
      "type": "score",
      "instructions": "根据 facts、rules 和 scoringDimensions，对执行 up 的总体合理性评分。只评估 up，不与其他动作比较。",
      "criteria": [
        "执行后立即失败或几乎必然失败",
        "风险很高，只有在没有其他可行动作时才合理",
        "风险较高或明显浪费回合，但没有立即失败",
        "风险可控，但既没有明显进展也没有明显损失",
        "风险较低，并且对通关有明确帮助",
        "安全性、进展性和后续机动性综合最佳"
      ]
    }
  }
}
```

## 8. 接口返回

`POST /api/decide` 成功时返回：

```json
{
  "model": "jev-latest",
  "direction": "left",
  "score": 4.2,
  "confidence": 0.87,
  "scores": {
    "up": {
      "direction": "up",
      "score": 2.1,
      "normalizedScore": 0.42,
      "confidence": 0.6,
      "probabilities": {},
      "legend": {}
    }
  },
  "facts": {},
  "rules": [],
  "scoringDimensions": [],
  "analysisUsage": {},
  "scoringUsage": {},
  "latencyMs": 1234
}
```

## 9. 错误处理

- 缺少 API Key：返回 503，AI 模式显示明确提示。
- DeepSeek 超时或上游失败：返回对应错误，AI 模式暂停并允许重试。
- DeepSeek 返回非 JSON 或结构不合法：返回 502，AI 模式暂停。
- Jev 超时、非 2xx、无效 JSON、缺少动作评分或评分越界：返回明确错误，AI 模式暂停。
- 不使用本地 AI 代替失败的分析或评分。
- 不向浏览器泄漏 API Key，不把 Key 写入日志、导出文件或页面。

## 10. 测试策略

### 10.1 DeepSeek 分析器

- 正常返回时提取合法 facts，并校验 facts 与原始快照一致。
- 非 JSON、缺少 facts、额外字段、方向建议字段或快照不一致时返回错误。
- 超时和错误状态映射正确。
- 请求体不包含 API Key。

### 10.2 Jev 评分

- 只为合法方向生成 score 问题。
- 正常响应提取 score 和 confidence。
- 非法方向、缺失评分、非数字评分、越界置信度均报错。
- 评分请求包含固定 rules 和 scoringDimensions。

### 10.3 选择器

- 选择最高分。
- 同分时选择更高置信度。
- 分数和置信度都相同时按固定方向顺序。
- 没有合法方向时拒绝执行。

### 10.4 集成

- `/api/decide` 正常链路返回方向、分数、置信度、facts、rules 和 usage。
- DeepSeek 失败、Jev 失败和 Key 缺失时均返回明确错误。
- 浏览器端显示四方向评分、最终动作、置信度、耗时和 token。
- 导出 JSON 保留 facts、规则、评分维度、Jev 评分和 usage。

## 11. 验收标准

1. DeepSeek 输出中不存在方向建议、动作排名或动作评分。
2. Jev 为每个合法方向返回独立 score 和 confidence。
3. 代码严格选择合法动作中的最高分。
4. 四个方向评分、置信度、最终动作和执行结果都显示并导出。
5. 任何上游失败都不会触发本地 AI 或擅自抢跑动作。
6. 原有 6 关可手动游玩，自动化测试全部通过。
7. 仓库中不包含真实 API Key。
